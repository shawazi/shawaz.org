03 · How I work

Evidence over optimism

Test that it runs

Green tests aren't the same as working software

I once inherited a repo with 398 passing tests that couldn't boot. It now has a required smoke-boot job, and on its first run that job found two real bugs.

Verify against reality

Mocks prove intent, not correctness

Third-party APIs get live contract suites and controlled experiments. That's how I learned one vendor returns 200 for fields it silently ignores.

Reproduce first

No fix without a failing test

Every bug fix starts with a test that fails for the right reason, and the fix is done when that test passes. That includes real phone calls for the voice agent.

Secure by construction

Make the wrong thing impossible

Row-level security, schema-level data isolation, single-use confirmation tokens, and constant-time signature checks. I put guarantees in code, not in docs.
